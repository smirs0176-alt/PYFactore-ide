# Журнал изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Подробный рабочий журнал прежних этапов — `docs/HISTORY.md`.

## [1.0.0] — кандидат в релиз (дату выпуска проставить при публикации)

Статус проверки см. в разделе «Известные ограничения» файла README.md: **сборка и запуск PyFactor.exe в Windows не проверялись**
(в среде разработки был только Linux); это нужно сделать по `docs/RELEASING.md` до публикации.

### Безопасность
- Ключи (Gemini, Resend, Google client secret, ElevenLabs) и токены хранятся в системном хранилище (Windows Credential Manager через `keyring`).
  Если хранилища нет, ключ пишется в `~/.pyfactor/secrets.json` открытым текстом — **теперь с явным предупреждением в окне**, а не молча.
  Переменная `PYFACTOR_REQUIRE_KEYRING=1` запрещает такую запись: сохранение завершается ошибкой.
- Ключ ElevenLabs раньше лежал открытым текстом в `settings.json` и не переносился; теперь хранится как остальные ключи, старое значение переносится при запуске.
- Текст запросов к ИИ больше не пишется в журнал `journal.md` (в нём бывает вставленный код с ключами).
- Раньше в исходниках были зашиты Google client secret и ключ Resend (см. `docs/HISTORY.md`). Из кода они убраны,
  но **считаются скомпрометированными: их нужно перевыпустить** (ротация), см. `docs/RELEASING.md`.
- Скрипт сборки релиза `scripts/make_release.py` проверяет файлы на секреты и не создаёт архив, если что-то нашёл.

### Исправлено
- `scripts/build_exe.py` перезаписывал рукописный `PyFactor.spec` (PyInstaller пишет .spec в текущую папку); теперь `--specpath build/`.
- `import pyfactor` импортировал Flask при каждом запуске (~0,25 с) ради функции, которую никто не вызывает, и прятал любые ошибки импорта.
  Теперь `pyfactor.register_pairing(app)` импортирует Flask лениво.
- Версия приведена к `1.0.0` (`pyfactor.__version__`), docstring пакета больше не обещает запуск `python pyfactor.py`.
- В README было неверно указано, что ключ Gemini лежит в `settings.json`.
- Линтер `ruff` проходит без замечаний.

### Добавлено
- Ресурс версии в `PyFactor.exe` (свойства файла в Windows): версия берётся из `pyfactor.__version__`.
- `scripts/make_release.py` — архив исходников `release/PyFactor-<версия>-source.zip` без кэшей, локального состояния, `legacy_unused/` и готовых бинарников `server/dist/`.
- Шаги CI: проверка версии в EXE, запуск EXE из папки с пробелами и кириллицей, аудит зависимостей, сборка архива.
- Тесты: хранение ключей и предупреждения, режим `PYFACTOR_REQUIRE_KEYRING`, ключ ElevenLabs, конфиденциальность запросов к ИИ,
  состав и чистота архива, сквозной сценарий в папке с пробелами и кириллицей (правка → автосохранение → запуск → ошибка → восстановление).

### Не входит в релиз
- `legacy_unused/` (старые копии модулей, остаются в репозитории, но не в архиве) и `server/dist/*` (готовые бинарники Go-сервера не воспроизводятся из исходников в этой проверке; собирай сам: `cd server && go build`).
