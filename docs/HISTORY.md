# Изменения этапа B (аудит безопасности)

Проверка: `python -m pytest` (36 тестов) и `cd server && go test ./...` (10 тестов).

## Клиент (pyfactor/)
- `core/utils.py` — `save_json` пишет атомарно, `private=True` даёт права 0600 (настройки, аккаунт, users.json).
- `core/paths.py` (новый) — имя из диалога не может выйти за пределы проекта (новый файл/папка, переименование, PG2).
- `core/process.py` (новый) — запускаемая программа не получает `PYFACTOR_*` ключи; остановка убивает всё дерево процессов; лимит вывода 5 МБ; необязательный таймаут (ключ `run_timeout` в settings.json, секунд, 0 — выкл.).
- `core/account/local.py` — PBKDF2 600 000 кругов, старые хеши обновляются при входе, минимум пароля 8 символов (новые регистрации).

## Сайт (site/)
- Адрес клиента за прокси — последнее значение `X-Forwarded-For` (раньше первое, его подделывал клиент).
- PBKDF2 600 000 кругов с миграцией: колонка `iter`, старые аккаунты входят и обновляются сами.
- `PENDING` (коды почты) очищается и ограничен по размеру.

## Go-сервер (server/)
- Токен не пишется в лог (файл `admin_token.txt`, 0600), минимум 16 символов, строгий `Bearer`.
- Блокировка после 10 неверных попыток с адреса за 5 минут (429).
- Атомарная запись состояния, проверка методов, очистка сообщения, защитные заголовки, `IdleTimeout`, мягкая остановка.
- `server/dist/*` пересобраны из этого кода (`CGO_ENABLED=0 go build -trimpath -ldflags="-s -w"`, Go 1.22). Подписи и контрольных сумм релиза пока нет.

## Несовместимо
- `ADMIN_TOKEN` короче 16 символов не принимается.
- Новые локальные аккаунты IDE: пароль от 8 символов.
- Имена файлов с `/`, `\`, `C:` в диалогах «Новый файл / Переименовать» отклоняются.

## Ещё не сделано
Хранение ключей в Windows Credential Manager, проверка имени модели Gemini и отмена запроса, схема URL сервера, GitHub-токен со scope `repo`, CI, Ruff-замечания (≈100), pyright/mypy, архитектура и интерфейс (этапы C, D).

# Этап B, продолжение (на твоей версии с secure_store)

## Почему «не соединился с сервером» (найдено и воспроизведено)
Сайт (`site/server.py`) и Go-сервер-выключатель оба по умолчанию слушали порт **8080**. Кто стартовал вторым — падал с `Address already in use`.
- Сайт теперь по умолчанию на **8081** (`SITE_PORT` по-прежнему меняет порт), а при занятом порте пишет понятное сообщение.
- Go-сервер остался на 8080. Старые `connect.json` с адресом `:8080` скачай заново на сайте.

## Исправлено
- `core/ai/gemini.py`: имя модели проверяется (оно шло прямо в адрес запроса), ответ ограничен 4 МБ.
- `core/secure_store.py`: когда секрет сохранён в системное хранилище (Credential Manager), открытые копии в `secrets.json` и старом `settings.json` стираются.
- `pairing.py`: коды и токены больше не пишутся в лог.
- `.env.example`: значения заменены заглушками; `.gitignore` дополнен (`.venv`, `.env`, `server/dist/admin_token.txt`, `*.db`).
- Тесты: `test_gemini.py`, `test_secure_store.py` (всего 66, все проходят).

## Убрано из архива (но не из твоей папки на диске!)
`.venv/` (61 МБ), `build/`, `dist/`, `.pytest_cache/`, `__pycache__/`, `server/dist/admin_token.txt`, `site/data/*.db`.

## Нужно сделать тебе
1. **Ротировать `RESEND_API_KEY`**: в `.env.example` лежало непохожее на заглушку значение. Если оно настоящее, создай новый ключ на resend.com и удали старый.
2. **Сменить `ADMIN_TOKEN` Go-сервера**: файл `server/dist/admin_token.txt` лежал в архиве. Перезапусти сервер с новым `ADMIN_TOKEN` (от 16 символов).
3. `PyFactor.spec` содержит абсолютные пути `C:/Users/Admin/Desktop/...`; для сборки используй `scripts/build_exe.py`.

## Не сделано / риски
- `pairing.py` — Flask-прототип без аутентификации (владелец пары берётся из запроса, `client_secret` принимается из тела). Не подключай к публичному серверу. Сейчас к сайту и IDE он не подключён.
- В `pyfactor/core` и `pyfactor/features` остались 30 модулей-дублей, на которые ничто не ссылается (около 6 100 строк, например `features/project.py` рядом с `features/project/`). Я их не удалял: `pg2/pg2.py` может запускаться как файл. Нужна отдельная уборка.
- Ruff (~100 замечаний), pyright/mypy, CI, отмена запроса Gemini, архитектура и интерфейс (этапы C, D).

# Этап: отмена ИИ, OAuth-безопасность, палитра команд, Ruff

## Gemini
- `core/ai/gemini.py`: запрос идёт через `http.client`, у него есть настоящая отмена (`Cancel.cancel()` рвёт соединение, `GeminiCancelled`). Отмена до соединения тоже срабатывает сразу.
- В чате ИИ кнопка «Спросить» во время ожидания превращается в «⏹ Отменить  Esc». Ответ отменённого запроса больше не меняет интерфейс; при закрытии окна запрос обрывается.

## Сайт (`site/server.py`): вход через Google и GitHub
- **`state` теперь проверяется** (раньше создавался и игнорировался): куки `oauth_google` / `oauth_github`, сравнение через `hmac.compare_digest`.
- **Захват чужого аккаунта закрыт:** почта GitHub берётся только с `verified: true` (раньше брался любой адрес из списка, в том числе неподтверждённый); из Google — только при `email_verified`.
- `site/google_login_example.py`: Flask больше не стартует с `debug=True` на `0.0.0.0`.

## Клиент
- Адрес сервера-выключателя: принимаются только `http://` и `https://` (`file://` и т. п. отклоняются), сеть `172.16–31.x` считается локальной.
- Импорт игры по ссылке: только `http(s)`, размер ограничен 5 МБ.
- **Палитра команд `Ctrl+Shift+P`** (`features/workspace/palette.py`): нечёткий поиск по реально существующим действиям и открытым вкладкам; есть в меню ☰ и в справке F1.

## Качество
- Ruff чистый (`ruff check .`), 34 проверенных исключения помечены `noqa` на месте. Это вызовы `subprocess` со списком аргументов, адреса с проверенной схемой и `exec` в интерпретаторе Fun. CI теперь запускает полный Ruff.
- В `legacy_unused/` дополнительно убраны сломанный `features/shell.py` (в `config` нет `ACT`/`BAR`; текущее окно уже содержит всё, что он описывал) и его старые зависимости.
- Тестов: 78 (с дисплеем), включая GUI-проверки отмены ИИ и палитры.

## Не сделано
`pyright`/`mypy`, проверка Windows, архитектурный рефакторинг (разделение миксинов на сервисы), Resend-ключ ещё настраивается из клиента (меню «Почта Resend…»).

# Этап E: аудит v5 → OAuth, токены, сборка EXE, подсветка

Проверялось в песочнице без tkinter, сети и Go: см. «Не проверено» ниже.

## Исправлено
- **Google OAuth (`core/account/oauth.py`)**: локальный приёмник на 127.0.0.1 принимал любой запрос с `code`/`error`, даже с чужим `state`: посторонний запрос мог сорвать вход. Теперь принимается только ответ с нашим `state` (остальные получают 400, ожидание продолжается), берётся первый верный ответ. Почта Google без `email_verified` отбрасывается. Тесты: `tests/test_oauth_loopback.py` (настоящие HTTP-запросы к приёмнику; на старом коде 2 из 3 падают).
- **Локальные аккаунты (`core/account/local.py`)**: повреждённый `users.json` читался как пустой, и следующая регистрация или вход перезаписывали файл, теряя всех пользователей. Теперь `AuthError`, рядом остаётся копия `users.json.corrupt`, исходный файл не трогается. Запись атомарная с `fsync` (через `utils.save_json`).
- **GitHub-токен (право `repo`)** лежал открытым текстом в `account.json`. Новый `core/account/vault.py` кладёт его в `secure_store` (Credential Manager при установленном `keyring`), старые файлы переносятся при первом запуске; если хранилище недоступно, токен остаётся в файле, а не теряется. Подключено в `ui/app.py` и `features/account/account.py`.
- **Сборка EXE**: `scripts/build_exe.py` теперь собирает `keyring.backends`, метаданные `keyring` и `pygments` (без этого EXE молча хранил бы ключи в файле); `os.pathsep` вместо жёсткого `;`. `PyFactor.spec` больше не содержит `C:/Users/Admin/Desktop/...`, `upx` выключен (ложные срабатывания антивирусов).

## Добавлено
- **Подсветка JSON, YAML, Markdown, TOML, INI, XML, shell, bat, SQL** через Pygments (BSD-2-Clause, необязателен; `core/web/pyg.py`, подключено в `ui/editor.py`, лимит 150 000 символов).
- CI: задание `windows` (pytest, сборка `PyFactor.exe`, артефакт).
- Тесты: `test_oauth_loopback`, `test_vault`, `test_pyg`, `test_build_config`, два теста в `test_site_and_accounts` (всего +15).

## Не проверено (честно)
- Окно IDE, правка `editor.py` и вызовы `vault` в миксинах: tkinter в песочнице нет, проверена только компиляция. Прогони `python -m pytest` на своей машине.
- Сама сборка EXE и новое задание CI на Windows; Go-сервер (`go` не установлен); Ruff; лицензии и актуальность зависимостей проверены только по метаданным локально установленного Pygments.

## Остаются риски
- OAuth GitHub по-прежнему запрашивает `repo` ради «Выложить на GitHub»; правильнее запрашивать при публикации.

# Этап F: аудит v6 — EXE, секреты, пара устройств, воспроизводимые тесты

Песочница без tkinter, сети, Windows, PyInstaller и Go: GUI-тесты и сборка EXE здесь НЕ запускались (см. «Не проверено»).

## Исправлено (подтверждено чтением кода; для каждого есть тест)
- **EXE запускал бы сам себя**: в сборке PyInstaller `sys.executable` — это `PyFactor.exe`, поэтому F5 открывал бы ещё одно окно IDE вместо программы (так же «весёлые» языки и пробный запуск функций). Новый `core/pyexe.py` ищет установленный Python 3 (`python_path` в settings.json, `PYFACTOR_PYTHON`, `py -3`, `python`, `python3`, каждый проверяется пробным запуском). Из исходников поведение прежнее. Если Python не найден — понятное сообщение в консоли.
- **EXE не находил файлы**: `pg2` (движок игр) и `funrun.py` запускаются с диска, а PyInstaller их не клал; `connect.json` искался во временной папке распаковки вместо папки рядом с `PyFactor.exe`. Исправлено в `scripts/build_exe.py`, `PyFactor.spec`, `config._app_root()`.
- **Сборка падала без keyring**: `--copy-metadata keyring` (моё же из v6) обрывал сборку, если keyring не установлен. Теперь keyring и pygments добавляются только если установлены.
- **Секреты в исходниках**: в `site/server.py` был зашит Google client secret (`GOCSPX-…`), в `pyfactor/resend_mail.py` — ключ по умолчанию (`AQ.Ab8…`) и личная почта в примере. Удалено; тест `test_no_committed_secrets` не даст вернуть. **Эти ключи нужно отозвать и выпустить заново: они уже были в присланных архивах.**
- **Сайт, вход через Google/GitHub**: (1) без включённых писем (`RESEND_API_KEY`) регистрация не подтверждает почту, и тот, кто зарегистрировал чужой адрес заранее, сохранял пароль после входа владельца через Google. Теперь у пользователя есть `verified`; вход через провайдера по неподтверждённому аккаунту меняет пароль на случайный и закрывает старые сессии. У уже существующих аккаунтов `verified=0`, поэтому при первом входе через Google/GitHub их пароль будет сброшен (вход через провайдера работает). (2) Адреса по умолчанию `SITE_URL` и `GOOGLE_REDIRECT_URI` указывали на мёртвый `pyfactor.xip.io` (без пути): вход через Google не работал, а при локальном запуске любой POST из браузера получал 403. Теперь по умолчанию пусто (берётся из Host), `/auth/google` без секрета сразу отвечает «не настроен».
- **Хранилище секретов**: токен устройства (связь с сайтом) лежал в `settings.json` открытым текстом, как и ключи Gemini/Resend/Google из старых версий. Теперь они переносятся в `secure_store` при запуске (`vault.migrate_settings_secrets`, `vault.cloud_*`). Повреждённый `secrets.json` больше не затирает остальные секреты: рядом остаётся `secrets.json.corrupt`.
- **Прототип пары устройств (`pairing.py`)**: любой мог создать код «от имени» чужой почты (владелец брался из тела запроса); погашение кода не было атомарным (гонка, проверено тестом); тело запроса не-объект давало 500, `force=True` принимал text/plain; Google-маршруты принимали `client_secret`/`client_id`/`redirect_uri` из тела, не проверяли `state` и отдавали токены Google клиенту; хранилище не ограничено; `str | None` падал на Python 3.9. Теперь: владелец из `Authorization: Bearer` через `create_app(auth=...)` (без него создание кодов отключено, 503), блокировка, хранение токена как sha256 + `owner_of()`, лимиты, серверный одноразовый `state`, ключи только из окружения.
- **Тесты**: зависимости объявлены (`requirements-dev.txt`: pytest, ruff, flask — раньше CI не ставил flask, и `test_pairing` падал бы); без tkinter тесты пропускаются, а не падают на сборе (`test_palette`, `norm_url`); `PYFACTOR_REQUIRE_GUI=1` в CI превращает отсутствие дисплея в ошибку, а не тихий skip; `python scripts/test.py` сам запускает xvfb в Linux.

## Не проверено (честно)
- GUI-тесты (`test_gui_smoke`, `test_palette`) не запускались ни разу: нет tkinter и дисплея. Проверен только импорт 64 модулей против заглушки tkinter. Правки в `runner.py`, `ui/app.py`, `features/account/*.py`, `ui/editor.py` в окне не пробовались.
- Сборка EXE и запуск готового EXE не выполнялись (нужны Windows и PyInstaller). Не проверено, подхватит ли EXE Credential Manager и найдёт ли системный Python.
- Тесты запускались не настоящим pytest, а моей минимальной заменой (вне проекта); нужен прогон `python scripts/test.py` у вас или в CI. Go-сервер, ruff, ветка Windows Credential Manager не запускались.

## Остаётся
- GitHub OAuth запрашивает `repo` только ради публикации. `PyFactor.exe` не подписан. Хранилище `pairing.py` в памяти одного процесса и к IDE/сайту не подключено. `_cleanup()` в `pairing.py` и подсветка/анализ выполняются под блокировкой/в потоке окна на больших данных. В `appengine.py` по-прежнему `sys.executable` (модуль не подключён к окну). В Windows без keyring секреты лежат в файле с правами пользователя (chmod там не действует).
