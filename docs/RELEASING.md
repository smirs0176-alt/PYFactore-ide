## 1. Перевыпусти скомпрометированные ключи (ротация)

В прежних версиях в исходниках были зашиты (подробности — `docs/HISTORY.md`):

| Что | Где было | Что сделать |
|---|---|---|
| Google OAuth client secret (начинался с `GOCSPX-`) | `site/server.py` | Google Cloud Console → APIs & Services → Credentials → твой OAuth-клиент → **создать новый секрет и отключить старый** |
| Ключ Resend по умолчанию (начинался с `AQ.Ab8`) | `pyfactor/resend_mail.py` | resend.com → API Keys → **удалить старый ключ, создать новый** |

Проверь, не попали ли они в историю Git и в уже опубликованные архивы (в присланном архиве `.git` не было, я это проверить не мог):

    git log --all -p -S"GOCSPX-" -- .
    git log --all -p -S"AQ.Ab8" -- .

Если находки есть, а репозиторий публичный или будет публичным, ротация обязательна; переписывать историю не требуется, если ключи отозваны.
Новые ключи вводи только через окно настроек IDE или переменные окружения (`.env.example` — шаблон, настоящий `.env` в git не попадает).

## 2. Проверь сборку в Windows (на реальной машине или в CI)

Требуется Windows 10/11 и Python 3.12 с tkinter (python.org).

    py -3.12 -m venv .venv
    .venv\Scripts\activate
    pip install -r requirements-dev.txt -r requirements-build.txt
    python -m pytest -q                 # все тесты; ожидается: 0 failed (1 тест Windows-only тоже должен выполниться, а не пропуститься)
    python scripts/build_exe.py         # результат: dist\PyFactor.exe

Или открой GitHub Actions → задание **windows** (оно делает то же самое, проверяет версию в EXE и 10 секунд запускает EXE из папки с пробелами и кириллицей).
**Зелёное задание — необходимое, но не достаточное условие**: оно не проверяет Credential Manager и «чистую» машину. Пройди ручной чек-лист на машине без Python и без `keyring`:

| # | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | ПКМ по `PyFactor.exe` → Свойства → Подробно | Значок PyFactor; версия продукта и файла `1.0.0` |
| 2 | Запуск двойным щелчком, потом запуск из папки `C:\Тест папка\` и из другой рабочей папки | Окно открывается, ошибок нет |
| 3 | Новый проект, файл `print("привет")`, F5 — **на машине без Python** | В консоли понятное сообщение «Не найден Python 3…», IDE не падает |
| 4 | Установи Python 3 (Add to PATH), повтори F5 | Выводится `привет`, а не открывается второе окно IDE |
| 5 | ⚙ → «Ключ Gemini…», введи тестовый ключ, перезапусти IDE | Ключ не спрашивается снова; в `%USERPROFILE%\.pyfactor\` **нет** `secrets.json` (если EXE собран с `keyring`) и в нём нет ключа открытым текстом; в Диспетчере учётных данных Windows есть запись PyFactor |
| 6 | То же на EXE, собранном **без** `keyring` | Появляется предупреждение о хранении открытым текстом |
| 7 | Запусти с `set PYFACTOR_REQUIRE_KEYRING=1` на сборке без `keyring` и введи ключ | Ключ не сохраняется, предупреждение объясняет почему |
| 8 | Вход через Google/GitHub с твоими `client_id`/`secret` | Вход проходит; при закрытии вкладки браузера IDE не зависает (ожидание заканчивается по таймауту, «Отмена» работает) |
| 9 | ИИ-чат: неверный ключ; отключи сеть; нажми «Отменить» во время запроса | «⚠ …» с понятным текстом; отмена мгновенная |
| 10 | Учётная запись Windows с кириллицей в имени пользователя | Настройки и ключи сохраняются между запусками |
| 11 | Закрыть окно во время работы программы из IDE | Дочерние процессы завершаются (Диспетчер задач) |

Результаты (пройдено / не пройдено, версия Windows, версия Python) запиши в описание релиза. Не пройденное — в «Известные ограничения».

## 4. Публикация (только после пунктов 1–3 и только с твоего решения)

    git checkout release/v1.0.0
    python scripts/check.py && ruff check . && python scripts/test.py
    python scripts/make_release.py                 # release/PyFactor-1.0.0-source.zip + SHA-256 (при секретах архив НЕ создаётся)
    git tag -a v1.0.0 -m "PyFactor IDE 1.0.0"
    git push origin release/v1.0.0 v1.0.0          # никаких --force

1. Скачай `PyFactor-windows` (EXE) из артефактов CI-задания для этого коммита; посчитай SHA-256:  `certutil -hashfile PyFactor.exe SHA256`.
2. GitHub → Releases → Draft a new release → тег `v1.0.0` → приложи `PyFactor.exe` и `PyFactor-1.0.0-source.zip`, впиши суммы SHA-256 и раздел `[1.0.0]` из `CHANGELOG.md`
   вместе со списком известных ограничений и результатами чек-листа из раздела 2.
3. Проставь дату выпуска в `CHANGELOG.md`.

Откат: пометь релиз как pre-release или удали (Delete release); тег и ветку не переписывай — выпусти `v1.0.1`.
